Jobs: visible background work. New job tools (`jobTools`, all `allow`): `job_start({ goal, total?, unit? })` returns `{ jobId }`, `job_update({ jobId, done?, total?, message?, image? })` and `job_end({ jobId, result?, status? })` answer a tiny `{ ok: true }`, so updates cost almost no tokens. The image is a PNG, JPEG, WebP or SVG file under `/workspace`, `/project` or the conversation folder (checked by content, symlinks never leave the roots, at most 5 MB, read again on each update) or a small data URL. Adopted agents get the new `jobs` tool set by default, and agents with the tools get a short `JOBS_NOTE` in their instructions. The server keeps each agent's jobs (`JobBoard`, `<dir>/jobs.json`): updates are throttled to about 4 per second (the latest wins, log lines accumulate, the last 50 are kept), jobs may outlive their turn, and running jobs become "interrupted" on a restart. Live `job` events reach the run stream (display only, never recorded). New routes: `GET /v1/threads/:id/jobs` and `GET /v1/threads/:id/jobs/:job/image` (an image only: no-store, a sandbox CSP). `/v1/activity` gains a "Jobs" group with the goal, the latest log line, the progress and the elapsed time. The app shows a live job card where `job_start` was called: the goal, a progress bar ("9/20 games · 45% · 3.1/min · ETA 4 min"), the latest log line with an expandable tail, the live image (click to enlarge) and the status (running, done, failed, interrupted); the `job_*` tool lines are hidden, and the Activity popover lists running jobs with their bar.
