Background commands. `run_command` accepts `background: true` (and `notify: false`): the command starts detached in the conversation's sandbox, marked with `AI_SDK_LETTA_BACKGROUND=1` so the cleanup after other commands (`KILL_SCRIPT`) spares it, with its output in `/workspace/.jobs/<id>/{out,err}` (not versioned), a heartbeat, and a wall-clock limit (`sandbox.backgroundTimeoutMs`, 6 hours by default, at most 48). The call returns at once with `{ jobId, note }`; its live command card starts right away and keeps updating after the turn, read from the files on the host. New tools, allowed by default in `SANDBOX_TOOL_PERMISSIONS`: `command_status`, `command_output` (bounded tail) and `command_stop`. The sandbox is never idle-stopped while one runs (the idle timer resumes after), and a session that closes keeps it until they end. After a restart, commands whose sandbox is gone are marked `interrupted`; running ones are followed again and get their card back. The server sends the agent one notification turn when a command ends ("[Background command finished] `python play.py` · exit 0 · 14 min · last lines: …", with a reminder to check and report), through the normal queue like decision outcomes: never behind an uncertain turn, never twice (its run ID derives from the command), not for `notify: false` or the agent's own `command_stop`. The app shows it as a compact line; cards and the Activity view have a Stop button for running background commands (`POST /v1/threads/:id/jobs/:job/stop`). `run_command`'s description and `JOBS_NOTE` tell the agent to use `background: true` for anything longer than a few minutes and not to poll. New exports: `BackgroundCommands`, `backgroundCommandsAt`, `backgroundScript`, `backgroundNotice`, `backgroundRunId`, `BACKGROUND_LIMITS`, `BACKGROUND_MARK`, `BACKGROUND_NOTE`, and in the server `BackgroundNotifier`, `RunBackground`.
