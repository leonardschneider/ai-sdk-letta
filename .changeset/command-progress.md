Live output and progress of long commands. When a `run_command` or `run_command_online` call runs longer than about 3 s in a turn with jobs, it gets an automatic job card (`kind: "command"`, goal `$ <command>`): its output is read from the sandbox every second (a separate `exec` on the same container reads the command's capture files, so it works with Docker, Apple Container and any session that allows concurrent runs), the latest lines become the log, and progress is parsed from tqdm bars (`45%|████▌ | 9/20 [00:12<00:15, 1.35it/s]`, with rate and ETA), `N/M`, pip downloads and `NN%`, handling `\r` redraws. The card ends with the command: done on exit code 0, failed with the exit code, or timed out. No card is made for quick commands, or when the agent is already reporting its own job. What the model gets is unchanged. New exports: `commandJob`, `parseProgressLine`, `visibleLine`, `OutputLines`, `commandGoal`, `pollScript`, `parsePollOutput`, `pollCommandOutput`, `COMMAND_PROGRESS`; `runSandboxCommand` and `SandboxManager.run` accept `onOutput` and `polling`. `JobDesk` gains an optional `agentJobActive(conversationId)`; `job_update` requests may carry `ratePerSecond` and `etaSeconds` (the reported values win over the measured ones). The app shows the card in place of the command's line, with the command and its output one click away.
